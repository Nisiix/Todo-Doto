1. Install and update

Download the setup, the .msi installer or the portable executable (it runs without installing anything) from the main page. Each file contains one language (English, Italian, French, German or Spanish), which you can then change in Settings › General. No administrator rights are needed. If Windows shows “Windows protected your PC”, choose “More info → Run anyway”: the warning is about the program being new, not about its safety.

On the first page of the setup an optional checkbox, unticked, also installs the free local AI (about 4 GB to download). If the download fails the app stays installed and you can turn the AI on later from Settings.

At every start the app checks whether a newer version is out: if so it shows “Update Todo Doto” with the download links, and you need to install it before continuing. The same happens if a colleague has already opened the workspace with a newer version: this way two different versions never rewrite the same files. To update, install the new version over the existing one: workspace data are not touched. The first time you open the app after an update a box sums up what’s new; it closes with “Got it” and does not come back. The notes for every version are on the Release notes page.

2. Create a workspace

A workspace has two folders: the projects folder (where they are, or where you will create them) and the Todo Doto data folder, separate from the first, where the app stores tasks, comments and history. At first start choose:

  • Create workspace: name, projects folder and data folder. “Only on this PC” to work on your own, with both folders on the PC; “Shared on the network” for the office, with the data folder on a server (see below).
  • Open folder: if a colleague has already created the workspace on the server, or for a folder that already contains projects.

If the chosen folder already contains projects (subfolders with .git, package.json, .sln, Cargo.toml, pyproject.toml, go.mod…), the app lists them and offers to create them all in the workspace: name from the folder, Stack derived from the files. At the next start the last workspace reopens by itself (you can turn this off in Settings › General).

3. Share with colleagues

There are no passwords: every PC has its own key, protected by the Windows user, and the data in the data folder are always encrypted.

  1. Whoever starts the workspace chooses “Shared on the network” and a data folder on the server (for example \\server\shared\Todo Doto or Z:\Todo Doto). They become administrator. The projects folder can also be local, as long as every PC uses the same path (e.g. D:\Dev).
  2. Right after, the app offers to save the recovery key: a .tdkey file protected by a passphrase you choose (at least 10 characters). Keep them safe and apart: they let you back in as administrator if every administrator PC is lost. Until it exists, administrators see a reminder; you can also create it later from Workspace management › General › Security.
  3. Each colleague installs the app and uses “Open folder” on the same data folder. Their PC asks for access and shows “Waiting for approval” with the code of the PC.
  4. An administrator opens Members, finds the request and, before pressing “Approve”, compares the code with the one the colleague reads on their screen (in person or by phone). They choose “As a new member”, or “As a new PC of …” if it is the second PC of someone already there. The PC gets in by itself within a few seconds.
  5. From then on everyone’s changes appear on the other PCs within a few seconds, with an “Updated by …” notice and the row flashing. Whatever happens while you are disconnected reaches you as notifications when you reopen.

From Members an administrator can also revoke a PC or remove a person: the keys are replaced and that PC can no longer read what is written from then on. Requirements: everyone needs read and write permissions on the data folder. Anyone opening the files with File Explorer or other programs reads nothing, and restricted projects can only be read from the PCs of the people who see them.

4. Projects, folders, tasks

In the left column administrators create folders (nested too) and projects. A new project is created from its folder on disk (which gives it its name), by copying the Stack of an existing project, from a project template or from a GitHub repository. The open project shows its sections below it: Stack, To-do, Kanban, Gantt and Attachments. Moving a project to the trash or deleting it only affects the workspace: the project folder and its files are never touched.

Every task has a title, description, priority (low, medium, high, urgent: the colored bar on the left grows with urgency), status (to evaluate, to define, confirmed), due date (only with confirmed status), assignee and label. In the detail you can add a checklist, an estimate in hours, the milestone, dependencies (“to do after” other tasks: while those are open the task shows a padlock) and a weekly or monthly repeat, which creates the next task when you complete it.

Quick add above the list creates a task as you type, for example CSV export !high @mario #bug by friday: priority, assignee, label and due date are recognized before you press Enter; ~v1.3 sets the milestone and =3h the estimate. It also works in the title of the “New task” dialog.

The list is sorted by priority, then by due date. In network workspaces the “Only mine” button, on when you open the page, shows only the tasks assigned to you or created by you: press it to see everyone else’s too. Filters narrow by due date, status, priority, “assigned to”, “created by”, label and milestone. “Attention” lists what is going wrong without anyone having flagged it: overdue tasks, urgent tasks with nobody on them, unanswered questions, stuck tasks.

Complete a task with the circle next to its title (or C); trash it from the menu (or Del). From the Trash you restore it or, administrators only, delete it permanently. Tasks completed more than 90 days ago stay at the bottom of “Completed”, hidden until you show them. Search (Ctrl+K or /) looks in all projects, archived tasks included; typing > shows the app’s commands and + adds a task to the open project.

5. Kanban and Gantt

Kanban shows the project’s tasks in columns, with the same filters as the list. Drag a card (or, with the card selected, Shift+←/→) to change its status, complete it or reopen it. “Completed” keeps the tasks finished in the last 14 days.

At first there is one column per status. With “Columns” an administrator gives the project its own columns: name, color, an optional task limit (the header changes color when it is exceeded, but nothing is blocked) and the status the column is tied to, so filters, Gantt and emails keep working. “Development template” suggests Backlog, To analyze, Ready, In progress, Code review, Testing; columns can be copied from another project. “Completed” is always the last one.

Gantt shows confirmed tasks with a due date, grouped by label or priority, with today’s line, weekends and milestones. Arrows link tasks that depend on each other and the longest chain of open tasks is highlighted.

6. Today and Week

Today, in the sidebar, gathers what concerns you across all projects: overdue, due today, questions waiting for your answer, answers to your questions, urgent and due this week. You complete and snooze (until tomorrow, until Monday, for a week) without opening the project; snoozing is just for you and does not change the due date.

Week (Ctrl+Shift+F) puts the same tasks on the days from Monday to Friday. Dragging a card onto a day plans when you will work on it, without changing the due date; “To catch up” collects past days whose task is still open. With the star you pick up to 3 commitments for the week. Capacity compares estimated hours with your weekly hours, minus absences (Members › Availability). From Friday afternoon a box offers to carry what is still open over to next week.

The Overview, at the top of the sidebar, shows what to keep an eye on in the next seven days, open questions, who is working on what (in a task’s detail, “I'm working on it”) and what this PC is missing for your projects.

7. Stack and PC setup

The administrator describes what the project is made with: application type, languages, frameworks, repository, project folder, notes, prerequisites (with version, link and check command), ordered steps (command, link or manual operation) and environment variables. Typing the name of a known tool (Node.js, Git, Rust, .NET SDK, Python…) fills in version, link and command; adding languages or frameworks suggests the prerequisites they need.

The Stack can also fill itself: “Detect from the project files” reads the folder (network folders too), “Import .md” reads a README or an architecture document, GitHub derives it from the repository. If the project files change later (for example a new Node.js version), a notice in the header offers to update the Stack in one click.

Set up on your PC: the procedure as a checklist, with commands to copy and links to open. The app checks the installed prerequisites by itself (version found, to update, missing). “Manage automatic setup” does everything from the app: it installs with winget the missing programs it knows how to install, then runs the steps in the project folder one after another, stopping at the first error; manual steps wait for “Done, continue”. You can also save the script to run it elsewhere. In network workspaces the result is shared: in the Stack a banner warns if someone is missing a prerequisite.

For a new PC, Set up this PC in the Overview installs in one go the programs all your projects need, each one only once. At the bottom of the Stack are the project’s AI tools: connectors, plugins and skills (attached as files, for example SKILL.md).

8. GitHub and commits that close tasks

An administrator connects GitHub in Workspace management › Integrations, with a read-only personal token stored encrypted on their PC. From the GitHub page in the sidebar (visible to administrators) they create projects from repositories: the Stack is derived from the repository files and re-syncs from “Sync” or automatically when the workspace opens.

Every task has a TODO-n code. Writing closes TODO-12 in a commit message (also fixes, resolves, or the Italian chiude; several tasks separated by commas), when the project opens the app reads the latest commits of the branch and completes the task, noting which commit did it. Turn it on in the Stack with “Close tasks from git commits”; it only works if the project folder contains .git, and the app never writes to the repository. The task detail shows the commits that mention it and the branch name to copy (git switch -c todo-12-…).

9. Questions, decisions, attachments

Opening a task brings up the detail panel: title, description and attributes are edited together and saved with “Save” (or Ctrl+S); if a colleague changes the task meanwhile, only the fields you are not touching are updated. In comments and questions you tag a colleague with @name. Questions have nested answers; whoever asked (or an administrator) marks them “resolved” or picks an answer as the decision, with the rationale. “Decisions”, in the project header, is the log of every decision, with search and copy as Markdown.

When you hand a task over to someone else, the detail suggests a handoff note with status, checklist, blockers and open questions, to add as a comment.

Attachments have a section of their own: files on the server, links or Google Drive documents, in attachment folders. Images, PDFs, text and web pages are previewed inside the app; one click opens the original. Google Drive is set up in Workspace management › Integrations; everyone connects their own Google account in Settings › Profile.

10. Notifications, email and Teams

Notifications (bell at the top) report what others did on the projects you see; choose which to receive in Settings › Notifications. In the same panel, “Announcements” collects the messages an administrator writes to everyone, to administrators or to whoever sees a project.

Emails (network workspaces) are optional:

  • An administrator chooses how to send them in Workspace management › Email and Teams: with Outlook on the PC or with the company SMTP server, with “Send me a test”. There they also set the allowed domains, the daily sends (the day’s summary and, on Mondays, the week) and the PC that sends them: ideally a service PC that is always on.
  • Everyone enters their address in Settings › Notifications › Your emails and confirms it with the 6-digit code they receive: nothing arrives until it is confirmed. Then they choose the topics (mentions, assigned tasks, answers to my questions and more).
  • Every personal email has a link that opens the app right on the task.

Each project can have a Microsoft Teams channel (in the Stack): the administrator pastes the address of a Teams Workflow and picks the events to post. In Settings › Calendars you turn on due-date calendars (.ics), yours and one per project, to open in Outlook or Thunderbird. When you close the window, queued emails are sent right away.

11. Roles, permissions, Activity

  • Administrator: everything, including approving PCs, roles, permissions, Stack, columns, permanent deletion, Workspace management and backups. Whoever creates the workspace is one; they can appoint others from Members.
  • Cleaner: like a member, but can move any task to the trash.
  • Member: creates, edits, completes, restores; trashes only tasks assigned to them or, if unassigned, created by them.

A project is public (visible to all members) or restricted (only to the chosen users, plus administrators): you decide when creating it and change it in the project header; users are assigned from the Members page → “Manage permissions”. A restricted project has its own key: whoever cannot see it cannot read it, not even by opening the files. In Members everyone also sets their Availability (hours per week and absences), which shows when someone assigns them a task.

The Activity page has three tabs. “What changed” (for everyone) compares two moments, for example the backup from a week ago and now: tasks added, completed, trashed, due dates moved. “Activity log” and “Analytics” are for administrators: the first records who did what; the second shows tasks by status and priority, overdue tasks, load per person and per week, project health and which PCs are ready for each project.

In Workspace management administrators also find Automations (alert for urgent tasks with nobody on them, for questions unanswered for days, asking for a due date when a task is confirmed) and the guided Cleanup (labels never used, empty folders, idle projects, old trash).

12. Milestones, reports, templates

Milestones (project header) are versions or releases with a target date: they show progress, appear in the Gantt and, once reached, write the release notes from the completed tasks, to copy or add to the project’s CHANGELOG.md.

From Documents you create the internal status report for a period (completed, delays, upcoming due dates, decisions) and the client roadmap, which shows what is done and what is coming without descriptions, comments or internal details. You can copy them, save them as a page to print to PDF or send them by email.

With “More › Save as template…” an administrator saves a project as a template: Stack, columns, attachment folders, milestones and tasks. A new project created from the template starts again with dates from today.

13. Local AI

The local AI is optional, free and runs entirely on your PC (Ollama with the Qwen 3 4B model, or an OpenAI-compatible server such as LM Studio): no data leaves the PC. Turn it on from the setup checkbox or in Settings › Local AI, which installs and starts Ollama if it is missing and downloads the models with a progress bar.

With the AI on you get: a more precise “Detect from the project files”, “How to fix” for unverified prerequisites, “From a text” (tasks drawn from notes, an email or minutes), a warning about similar tasks, search by meaning, commits that may have completed a task, the weekly summary, AGENTS.md and CLAUDE.md written from the Stack, and “Ask”, which answers questions about the project from tasks, decisions, Stack and attachments, citing the sources. Every suggestion has to be confirmed.

14. Away from the office and VPN

With “Keep a copy of the workspace on this PC” (Settings › Profile, on by default) you keep working even when the shared folder does not respond: “Away from the office” appears at the top with the projects still to send. You can change existing tasks and projects; when you are back, the changes are merged with your colleagues’ field by field, and a report shows the rare conflicts.

In Settings › Profile › Office connection (VPN) choose a VPN already set up in Windows: Todo Doto connects it by itself when the shared folder does not respond. Credentials stay with Windows. Over VPN the screen updates right away and files are written in the background; if you close the window while a save is in progress, the app waits for it to finish (a second click on the X closes right away).

15. Backups

The workspace is a folder: the server backup includes it. On top of that the app makes a backup by itself every day (.pgmbackup files in the data folder, encrypted like the rest) and keeps 7 daily and 4 weekly ones. In Workspace management › Backup the administrator creates a backup by hand, chooses another folder (better another disk or server) and restores the whole workspace or a single project; before every restore a copy of the current state is saved, so even a restore can be undone. The PC keys are not in the backups: keep the recovery key safe. Every deletion by the app stays confined to the data folder: your project files are never touched.

16. Shortcuts

  • N new task in the open project
  • Ctrl+K or / search all projects; > for commands
  • ↓ from the page to the first row, then ↑ ↓ to move, Enter opens, C completes, Del trashes
  • Shift+←/→ moves the selected card in Kanban and Week
  • Ctrl+Shift+F Week, Ctrl+, Settings
  • Ctrl+Enter creates from the dialog, Ctrl+S saves in the detail
  • Ctrl+Shift+L light/dark theme, Esc closes, ? shows all shortcuts

17. Common problems

“Folder unreachable, retrying…”

The server is not responding or the network is down. The app retries by itself; changes already saved are safe and, with the away-from-the-office copy on, you keep working. If it persists, check that you can see the folder in File Explorer or connect the VPN.

The PC stays on “Waiting for approval”

An administrator has to approve it in Members › Access requests, after comparing the code of the PC. The app checks again by itself every 10 seconds, or press “Check now”. If the request was rejected, reopen the workspace to ask again.

Every administrator PC is lost

From a new PC open the data folder and, on the waiting screen, choose “I'm an administrator: use the recovery key”: pick the .tdkey file and enter its passphrase. Without a recovery key nobody can approve new PCs any more: that is why the app offers it as soon as the workspace is created.

“Update Todo Doto” appears at start

A newer version is out, or a colleague has already opened the workspace with a newer version. Download and install the suggested version: no data are lost.

I don’t receive emails

Check in Settings › Notifications › Your emails that the address is “Verified” and the topics are on. If the code does not arrive, an administrator has to turn sending on in Workspace management › Email and Teams and check that your domain is among the allowed ones. Look in the spam folder too.

Colleagues’ changes arrive late

On some servers change notifications do not arrive: the app checks anyway every few seconds and when you come back to the window. A longer delay points to a slow network.

Over VPN or with a slow server, saving takes time

The screen updates right away and files are written in the background; if a write fails, the app says so and goes back to the server’s state. To find out how fast the folder is from this PC open Settings › Profile › Shared folder speed and press “Measure”: you see the server’s response time, how long a save takes and whether it is a local network, a slow network or a VPN. “Copy for IT” prepares the results to pass on to whoever runs the server.

If the measurement points to an antivirus, ask IT to exclude the *.lock and *.tmp files of the data folder from real-time scanning: the app creates and deletes them at every save, and scanning them all can double or triple the times. To work away from the office for long, keep the copy of the workspace on this PC turned on in Profile.

“Set up on your PC” does not appear in the Stack

It appears only if the project folder is valid on this PC: it exists, contains a recognizable project and has the same name as the project. The box explains why and lets you look for it; the chosen folder is remembered for this PC.

A prerequisite shows “not found” even though it is installed

It is probably not on the PATH: the app says so when it finds it in the standard install location. Close and reopen the prompt after installing, or use “Check again”. An uncertain result can be confirmed by hand by ticking the circle.

Didn’t find the answer? Write to nisos@live.it or use “Send a report” in Help and information, in the workspace menu.
