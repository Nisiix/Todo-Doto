1. Install and update

From the home page download the setup, the .msi installer or the portable executable (runs without installing anything), in the language you prefer: each file contains one language, English or Italian. No administrator rights needed. If Windows shows “Windows protected your PC”, choose “More info → Run anyway”: the warning is about the program being new, not unsafe.

To update, install the latest version over the existing one: workspace data is never touched. What changed in each version is on the Release notes page and in the Releases feed.

2. Create a workspace

A workspace has two folders: the projects folder (where they are, or where you will create them) and the app data folder. On first launch choose:

  • Create workspace: name, projects folder and data folder. “Only on this PC” to work alone; “Shared on the network” for the office (see below).
  • Open folder: when a colleague already created the workspace on the server, or a folder that already contains projects.

If the chosen folder already contains projects (subfolders with package.json, .sln, Cargo.toml, pyproject.toml, go.mod…), the app lists them and offers to create them all in the workspace: name from the folder, Stack read from the files. In that case the workspace data goes in another folder, suggested next to it. On the next launch the last workspace reopens by itself.

3. Share with colleagues

  1. Whoever starts the workspace picks a folder on the server (for example \\server\shared\Roadmap or Z:\Roadmap), the “Shared on the network” mode and a password of at least 6 characters. They become the administrator.
  2. Every colleague installs the app, uses “Open folder” on the same folder and enters the password; they can choose to remember it on their PC, encrypted by Windows.
  3. From then on everyone’s changes show up on the other PCs within seconds, with an “Updated by …” notice and a flashing row. Whatever happens while you are away reaches you as notifications when you reopen.

Requirements: everyone needs read and write permissions on the folder. The password protects access through the app, not the files: anyone who can open the folder in File Explorer can read them.

4. Projects, folders, tasks

In the left column you create folders (nested too) and projects. A new project is created from its folder on disk (which gives it its name), from the stack of an existing project (“New project with this stack”) or from a GitHub repository. The open project shows its sections underneath: Stack, To-do, Gantt and Attachments.

Every task has a title, description, priority (low, medium, high, urgent: the colored bar on the left grows with urgency), status (to evaluate, to define, confirmed), due date (confirmed status only), assignee and label. The list is sorted by priority, then due date. Filters narrow by period, status, priority, “assigned to”, “created by” and label; search (Ctrl+K or /) looks across all projects.

Complete a task with the circle next to its title (or C); trash it from the menu (or Del). From the Trash you restore it or, administrators only, delete it permanently. The Gantt shows confirmed tasks with a due date, grouped by label or priority, with today’s line and weekends.

5. Stack and PC setup

The administrator describes what the project is built with: application type, languages, frameworks, repository, project folder, notes, prerequisites (with version, link and check command), ordered steps (command, link or manual operation) and environment variables. Typing the name of a known tool (Node.js, Git, Rust, .NET SDK, Python…) fills in version, link and command; adding languages or frameworks suggests the prerequisites they need.

The stack can also fill itself: “Detect from project files” reads the folder (network folders too), “Import .md” reads a README or an architecture document, GitHub reads it from the repository. The stack’s initial files (package.json, .gitignore…) accept the {{name}} and {{slug}} placeholders.

Set up on your PC: the procedure as a checklist, with commands to copy and links to open. The app checks installed prerequisites by itself (version found, to update, missing) and “Start setup” runs the checks and steps in a command prompt window, in the project folder, stopping at the first error. In network workspaces the outcome is shared: a banner in the Stack warns the administrator when someone is missing a prerequisite.

At the bottom of the Stack, the project’s AI tools: connectors, plugins and skills (attached as files, for example SKILL.md).

6. GitHub and commits that close tasks

From the GitHub page (next to Drive) you connect with a read-only personal token, stored encrypted on your PC. From the repository list the administrator creates projects: the Stack is read from the repository files and re-syncs from “Sync” or automatically when the workspace opens.

Every task has a TODO-n code. Writing closes TODO-12 in a commit message (also fixes, resolves; several tasks separated by commas) makes the app complete the task when the project opens, noting which commit did it. Enable it in the Stack with “Close tasks from git commits”.

7. Questions, comments, attachments

Opening a task shows the detail panel: title, description and attributes are edited together and saved with “Save” (or Ctrl+S). In comments and questions you tag a colleague with @name: they get a notification. Questions have nested answers; whoever asked (or an administrator) marks it “resolved”. The workspace home page lists the open questions of every project.

Attachments have a section of their own: files on the server, links or Google Drive documents, in attachment folders. Images, PDFs, text and web pages show inside the app; one click opens the original. Notifications (bell at the top) report what others did; choose which to receive in Settings.

8. Roles, permissions, Analytics, activity log

  • Administrator: everything, including password, roles, permissions, stack, permanent deletion and backups. Whoever creates the workspace is one and can appoint others.
  • Cleaner: like a member, but can move any task to the trash.
  • Member: creates, edits, completes, restores; trashes only tasks assigned to them or created by them.

A project is public (visible to every member) or restricted (to chosen users, plus administrators): decided at creation and changed in the project header; users are assigned from the Members page → “Permissions”. The Analytics page (administrators) shows tasks by status and priority, overdue and due soon, open questions, load per user and per project. The activity log records who created, completed, trashed, restored or deleted what.

10. Backups

The workspace is a folder: the server backup includes it. On top of that, from Settings the administrator creates and restores workspace backups (.pgmbackup files in the data folder). Every deletion the app performs stays inside the data folder: your project files are never touched.

11. Shortcuts

  • N new task in the open project
  • Ctrl+K or / search across all projects
  • ↓ from the page to the first row, then ↑ ↓ to move, Enter opens, C completes, Del trashes
  • Ctrl+Enter creates from the dialog, Ctrl+S saves in the detail panel
  • Ctrl+Shift+L light/dark theme, Esc closes, ? shows every shortcut

12. Common problems

“Folder unreachable, retrying…”

The server is not responding or the network is down. The app retries on its own; saved changes are safe. If it persists, check that you can see the folder in File Explorer.

Colleagues’ changes arrive late

On some servers change notifications never arrive: the app still checks every 4 seconds and when it comes back to the foreground. A longer delay means a slow network.

“Set up on your PC” does not appear in the Stack

It appears only when the project folder is valid on this PC: it exists, contains a recognizable project and is named like the project. The box explains why and lets you look for it; the chosen folder is remembered for this PC.

A prerequisite shows as “not found” although it is installed

It is probably not in the PATH: the app says so when it finds it in the standard install location. Close and reopen the prompt after installing, or use “Check again”. An uncertain outcome can be confirmed by hand by ticking the circle.

The password is not accepted

The administrator may have changed it: enter it again. If you forgot it, the administrator resets it from Settings.

Didn’t find the answer? Write to supporto@projectgoalmanager.app or open an issue on GitHub.
